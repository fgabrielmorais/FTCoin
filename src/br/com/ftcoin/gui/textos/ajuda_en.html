1. Overview

FTCoin Studio is an academic application for managing wallets of the FTCoin virtual currency, recording purchases and sales, checking quotes and tracking results. Use the buttons in the top bar to open each screen.

2. Wallets

  • Create: open Wallets, click New Wallet, enter the holder and broker, and confirm.
  • Edit: select a wallet in the table and click Edit to change its details.
  • Delete: select the wallet and confirm deletion. Wallets with recorded transactions cannot be deleted.

3. Purchases, sales and dates

Open Transactions, choose Purchase or Sale, select the wallet and enter a positive quantity. Use a dot or comma as the decimal separator, without thousands separators: for example, 10.5 or 10,5. Check the details and confirm the transaction. Sales exceeding the available balance are rejected.

Enter dates as YYYY-MM-DD, for example, 2026-11-01, regardless of the selected language. The transaction form rejects future dates.

Current limitation: the entered date may be used for the estimate, but the purchase or sale is recorded using the current computer date and validated using the current quote. To keep the estimate consistent with the record, use the current date. The form cannot record a backdated transaction.

4. Quotes and cache

On the Quote screen, enter a date as YYYY-MM-DD and click Consult. The screen displays the value, response source, response time and query time.

  • Oracle: a query to the configured quote source. Memory mode uses simulated values; MariaDB mode reads them from the database. This is not an integration with an exchange or external financial service.
  • Cache: temporary reuse of a previously queried quote, valid for 60 seconds. The cache is cleared when the database is switched.
  • Clear cache: removes temporary entries and queries the current date again.

If there is no quote for the requested date, the system says so instead of making up a value. Days without a quote are left out of the recent history.

5. Using the reports

Open Reports and select a wallet for reports 1 and 2. Use Refresh All to reload the data.

  1. Consolidated position: balance, average cost, cost value, market value, gains and ROI for the selected wallet.
  2. Transaction history: dates, purchases and sales, quantities, quotes and totals for the selected wallet.
  3. Consolidated portfolio: all wallets and their respective shares of the total market value.
  4. Performance and profitability: cost value, current value, total result and ROI per wallet. The table is not necessarily sorted by profitability.
  5. Oracle history: a table of recent quotes, absolute and percentage changes, and the source indicated by the system.

6. Average cost and results

Weighted average cost (CMP): cost value divided by the FTC balance. A purchase increases the balance and cost value, recalculating CMP. A sale reduces the balance and cost value proportionally, preserving CMP subject to rounding.

  • Realized result: the sum of sale results. Each sale yields quantity sold × (sale quote − average cost).
  • Unrealized result: market value of the remaining position minus its cost value.
  • Total result: realized plus unrealized result.
  • ROI in this application: total result divided by the cost value of the remaining position, multiplied by 100. When this cost value is zero, the system displays zero ROI.

Negative results represent losses. Colors assist reading, but also check the displayed sign and value.

7. Language and storage

Use the Language selector in the top bar to choose Portuguese, English or Spanish without restarting. Close modal dialogs, such as this manual, to access the selector, then reopen Help. The language changes the presentation of text, numbers and dates; it does not represent a currency conversion.

The Database selector switches between Memory and MariaDB. Switching selects another data source; it does not automatically transfer records between modes.

  • Memory: intended for tests and simulations. Data is not stored permanently and is lost when the application exits.
  • MariaDB: records are persisted in the configured database. If the connection fails, check that the server is available and ask the person responsible for installation to check the address, database, credentials and permissions. Do not share passwords in screenshots.

8. Exiting

To close only this manual, use Close Manual or the X on this window. To exit the application, use the X on the main window. Complete transactions before exiting: unconfirmed fields are not saved records, and memory-mode data will not be available in a new session.
